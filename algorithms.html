Artifact Narrative

Artifact description

The artifact selected for this enhancement is QuestionableCode.cpp, a C++ static-analysis exercise created during earlier CS 405 and CS 410 coursework. The original program intentionally includes endless recursion, unchecked indexed access, iterator invalidation, inefficient summation, and broken pointer traversal. I created the algorithms and data-structures enhancement in July 2026 and revised it in August 2026. The original remains unchanged. The final enhancement consists of a reusable public interface and implementation, an ordinary demonstration program, a separate verification suite, and a separate performance comparison.

Justification and improvements

I selected this artifact because it demonstrates that I can examine existing logic, identify why it is unsafe or inefficient, choose an appropriate algorithm or data structure, and explain the trade-offs. The recursive type check was replaced with std::unordered_set, which provides average O(1) membership lookup. The unchecked array write became a bounds-checked std::vector update that returns success or failure. Unsafe deletion during iteration became the erase-remove idiom, which removes matches in O(n) time without reusing an invalid iterator.

I also improved two areas beyond the initial plan. A loop-based inclusive range sum was replaced with the arithmetic-series formula, reducing the work from O(n) to O(1). The function validates the range, checks arithmetic overflow, and returns std::optional when a safe result cannot be produced. For the linked token structure, I implemented Floyd’s tortoise-and-hare algorithm. It detects cycles in O(n) time and O(1) extra space, finds the cycle entry, and counts unique nodes. This prevents endless traversal while avoiding an auxiliary visited-node set.

Reflection and feedback

The main lesson I learned is that a data structure or algorithm affects correctness, performance, readability, and security at the same time. Using a standard container does not automatically make an operation safe; indexes, iterators, arithmetic, and failure cases must still be managed. The most difficult challenge was implementing the constant-time range sum without creating overflow in intermediate calculations. I addressed it through validation, checked arithmetic, and an explicit optional result. Floyd’s algorithm was also challenging because detecting a meeting point was only the first step; I also had to locate the cycle entry and calculate the number of unique nodes.

Testing normal and edge cases strengthened my understanding of the algorithms. The verification suite contains 19 checks covering valid and invalid indexes, duplicates, missing values, overflow, empty chains, ordinary linked chains, and multiple cycle patterns. The project compiles under C++17 with warnings treated as errors and passes AddressSanitizer and UndefinedBehaviorSanitizer with 19 checks passed and no failures.

I incorporated the instructor’s final-polish feedback by moving all pass/fail reporting out of the reusable implementation and demonstration program and into AlgorithmsDataStructuresTests.cpp. I also added PerformanceComparison.cpp with 5,000 type names, 250 membership searches, and a range from 0 through 50,000,000. The revision improved reusability, separation of concerns, verification quality, and stakeholder communication.
